## 3. 页面组织、交互和现有缺陷（P1）

### 3.1 导航与返回

普通账号主导航：**今天、手账、计划、成长、我的**。复用现有组件和路由能力；新增计划主入口，不让低频配置占满今天。保留旧 `/journal`、`/events/:id`、`/checkin` 等可用链接或提供明确重定向。

- 今天：记事件、当日到期计划、可关闭的生活清单、晚间日记入口、近期记录摘要。
- 手账：事件/日记筛选、正文搜索、日期筛选、分页；详情中的完整依据按需展开。
- 计划：所有计划和数量、目标及当前主线、日程管理、当次历史；不把过去未完成的安排搬到今天。
- 成长：统计摘要、13 维数值/图表，挑战/商店/成就分标签或二级页；流水按需加载。
- 我的：账号安全、模型、导出、帮助；摘要加入口，不堆叠全部编辑表单。

所有二级页面在标题上方提供可见返回入口。管理账号安全页返回进入前的合法管理页面，无来源返回管理概览；普通页面按所属主区回退。使用本应用记录的合法来源/路由状态，不能只凭浏览器 history 长度返回外部网站；刷新/直接链接有稳定兜底。返回不退出登录、不切换身份。退出与返回是两个动作；切账号、切管理工作区和登出清理来源及未完成请求，不能用上一身份的来源串页。

有未保存输入时保留当前已有草稿恢复/离开保护；冲突不丢输入。管理端仅有管理导航，普通端不因隐藏菜单就获得权限。

### 3.2 时间、状态、文案与图表

- 事件默认本人时区当天；精确发生时间/其他日期折叠到低频入口，不每次强迫选择时间。
- 发生日期、发生时间精度、创建/保存时间分开。没有精确时刻就保存“日期精度”，不伪造 13:00 或把保存时刻声称为发生时刻。
- 正文写“昨天”仅可提示候选日期，由用户确认归档；不暗中移动记录。默认当天符合本轮需求。
- 原文已保存、是否分析、分析任务状态、建议状态、是否入账分别显示。用户后来主动分析了原“只记录”事件，就不能一直显示“本条选择了不分析”。
- 活动任务使用只读查询更新，进入页即读、可见时按现有任务节奏刷新；结束、离页、隐藏或切账号停定时器/取消旧请求。终态更新一次后停止，不通过重复提交分析来刷新。
- 配置帮助集中解释 Key/费用/用途一次，并保留帮助链接。已绑定模型的详情不重复写“分析前请绑定”；确实无可用配置才给配置入口。付费测试、重试等实际调用仍有简短说明，保存错误与任务错误就近保留。
- 未评估 50 起点显示“未评估基线/游戏起点”，不能显示能力“熟练”；不重置数值，不替已评估或迁入用户改来源标签。
- 雷达图标签完整可读、给出数值列表，不用多余横向滚动容器掩盖截字；历史图与完整解释可折叠。

### 3.3 响应式与兑换

按容器可用宽度适配，而非靠手机 User-Agent 决定功能。桌面侧栏/多列、手机单列/底栏、平板适度收列；表格窄屏转账号卡片等可读结构。图表、长模型 ID、中文标题、金币数、按钮各自检查，不能只检查全页 overflow。

兑换用应用内可访问对话框，显示物品、花费、剩余余额；有标题、焦点进入/约束/关闭后返回触发按钮，键盘可操作。取消零副作用。顶部金币仅保留紧凑摘要，完整流水不做覆盖页面的大面积吸顶区域。

兑换沿用原操作 UUID、原请求正文、物品版本和持久回执。网络结果未知保留恢复入口；已成功但读列表失败不提示“兑换失败”诱发重买。标记奖励券兑现不再扣币。禁止把修弹窗改成重写交易算法。

## 4. 模型配置、测试与帮助

### 4.1 当前配置与测试协议（P1）

保留现有主组/辅组和三家供应商，先修体验；不新增任意 Base URL 或未经评审的新供应商。摘要显示来源、provider、准确 model ID、用途、是否启用、验证结果和时间。实际一次分析保存其使用的 provider/model/配置版本，历史结果不能跟着新设置改成新模型名。

配置状态至少区分：未配置、已保存未验证、测试中、通过、失败、旧验证已失效、已停用。验证状态与启用状态正交；“已保存/已启用”不能冒充模型可用。错误模型名可保留待修输入，但必须显示尚未验证或明确测试错误，不仅弹“保存成功”。格式错误先本地校验；不存在/权限不足须主动联网测试才知道，保存不暗中调用供应商。

`GET /api/llm-config` 扩展摘要；`PUT /api/llm-config` 继续保留/替换/清除 Key 及换供应商重新绑定规则。测试入参使用已保存组身份与预期配置版本，例如 `{group, expected_config_version}`；不得把未保存表单正文当已生效配置测试。旧客户端兼容由 Writer 明确说明，不能静默测试旧值。

`POST /api/llm-config/test` 返回受控的 `status/provider/model/config_version/tested_at/error_code/message/retryable`。测试期间配置改变时拒绝旧结果成为当前“通过”；成功结果按配置版本保存，不保存明文凭据或敏感供应商响应。测试结果是时间点验证，不保证永久可用。

至少区分认证失败、模型不存在/无权限、余额/配额、限流、超时、服务错误、格式不兼容。供应商未返回足够信息时显示受控“请求失败”，不编造唯一原因；错误详情脱敏。测试以有界最小请求检查当前模型的聊天能力，JSON 业务输出适配另做检查；不能把 `Reply OK` 通过称为所有分析能力通过。

未保存编辑标记未保存，先保存再测试；测试期间禁重复按钮。通过/失败结果紧邻测试控件，读屏可获知状态。无模型仍可保存/回看/导出原文，现有余额与结果不丢。

### 4.2 首次配置指南

提供就近帮助入口：选择供应商 → 官方控制台创建 Key → 官方模型与价格页复制准确 ID → 回填主组 → 保存 → 主动测试 → 看结果与修复建议。解释供应商账号不同于 LifeXP 账号，主辅用途和必要时的回退规则。

官方入口取自 [API 资料第 4 节](API_CONFIG_AND_FREE_ACCESS_2026-10-15.md)，实现交付时重新核验并注明日期；新窗口使用安全属性。区分网页聊天免费、一次性赠送额度与零价格 API，不宣传“三家全免费”或“永久免费稳定”。本文件未重新验证 10 月 15 日后的价格或模型可用性，不能固定历史示例为生产推荐。

### 4.3 站点默认 AI（D06 通过后实施/启用）

候选界面保留“站点默认／我自己的模型／关闭 AI”，若没有正式托管服务就隐藏或标未开通，不能显示可用的假默认服务。

启用前确认供应商/模型、共享服务范围、个人日额度、全站并发/调用/token/费用预算与重试核算。独立服务端凭据存于受限秘密配置，不复用或复制 owner 私有 Key，不下发浏览器。用户主动开启并知道内容将发送到哪个供应商；不用默认选择触发历史全文后台分析。

任务保存凭据作用域、实际配置版本、停用版本和本人归属；换配置、取消或用户停用后旧任务结果不能覆盖。个人数据、提示上下文、缓存与账本始终隔离。配额预占/结算/失败释放须覆盖重试与超时；未知供应商计费结果不能简单当零费用无限重试。

免费候选失效、限流或价格变化时暂停/反馈，不偷偷改用付费服务或个人 Key。真实默认 AI 接入时补调用量、失败率、额度/预算的管理视图；Demo 每日 5/8 次不是正式配额。

## 5. 事件、晚间日记与辅助回顾（P2）

### 5.1 明确类型与旧数据兼容

新增明确 `record_kind=event|diary` 与记录日期/时区语义，旧 `source` 继续表示输入来源。当前 `source=journal` 既可能是自由记事件也可能是旧日记，不得一次迁移全当 diary。

新事件和新日记入口明确类型；晚间日记同日再次保存更新原稿版本，不每次新增一篇。旧同日多篇原文分别保留，不自动拼接；旧 DailyReview.note 保留原来回顾身份，不迁成日记冒领天数。

新日记编辑采用稳定的本人/日记日身份与幂等创建，双标签页首存只能得到同一稿件；后续保存必须带内容版本。唯一约束不能直接覆盖所有旧同日 journal 行，应为新入口设置可为空的独立日稿身份，旧多篇仍可分别读取。改时区不自动新造第二份原稿，按已保存日稿身份继续定位。

旧记录采用 `legacy_unknown` 或等价兼容标记与明确展示，D02 确认分类/统计前不凭内容猜测。已有事件和判定 ID、版本、实际属性/金币流水及审计不改写；类型增量不能让旧账失去关联。用户只把本轮云端数据视为测试，不等于授权清库。

### 5.2 单事件分析与关联

普通事件只追问该事件的事实/有效投入/结果；“部署项目”不扩展问昨晚几点睡、三餐、全天运动。睡眠本身作为事件时仍可问相关睡眠信息，不能机械禁止词语。信息足够可以直接给建议，不强制填满固定问题数。

模型 `merged_with` 等输出只产生“疑似同一事实”候选，提供本人记录 ID、版本和依据；验证引用存在且归属本人，用户确认后建立关联。未确认不显示“已合并”、不物理合并原文、不抑制结算或自动重算。既有已入账历史不得仅因模型新猜测而改变。

用户拒绝关联后，本次分析不再循环要求同一关联；新事实与重复描述的区别要能说明。正式关联/去重和新增成果结算按 D03 收束，语义不确定时不替用户决定。技术幂等仍照常生效，不能因关联未确认就允许双击重复入账。

分析输出展示事实摘要、所用规则/证据和建议原因，不要求生成或保存模型隐含思维链。判断与提示词不从事件正文中执行指令。

### 5.3 晚间日记入口与会话

一个入口中明确三类内容：**我的日记原文、AI 引导问题与我的回答、AI 分析**。AI 回答/分析不自动拼入原文；日记保存后可继续辅助回顾，保存回答独立生效，不要求再点一次保存日记。移除“此刻的感觉”按钮组；用户在原文主动写情绪不受限制。

用户主动开启 AI 时只读本人当天日记、事件、计划事实、已有清单及问答摘要，控制上下文大小。先检查已覆盖/已跳过主题，避免同义追问；没有缺口可直接结束。日记充分表达沮丧时可邀请回想尚未写的支持或轻松片段，但不强求积极、不否认原感受，也不重复已写的支持经历。

问题生成成功后先持久化再展示，存 question ID、顺序、确切文本、模型来源与时间；待回答/已跳过/已回答分开。未成功持久化的候选不能显示成已保存问题。刷新或重进继续同轮，不再次复制同一问题；回答明确关联 question ID，允许版本化修改而不覆盖历史。

回顾 session 关联本人、记录日/时区、原文版本及事件/计划版本快照；分析保存实际模型/提示词版本、引用问答版本、生成时间与终态。编辑日记后保留旧问答/分析的当时依据，新分析另存版本；不把过时分析贴成最新原文的结论。

问答或分析失败/取消不损坏原文和已存回答；旧任务晚到不得覆盖新版本。并行标签页继续同一会话、双回答、重复请求须有版本/幂等冲突处理，409 保留用户输入并提供比较/重试。

辅助回顾单独保存不新建日记日数、事件、第三套回顾连续天数或奖励。若用户另要把补充事实记成事件，必须显式创建/关联，并遵守同事实防重复。

### 5.4 可选生活清单

按用户认可方向提供睡眠、饮食、活动的轻量清单，可整体关闭、单项补记/跳过。没记录显示“还没记录”，不推断没做；已有明确事实可标已记，不因看起来相似就丢用户确认。

本轮不实现定时推送、系统通知或强制心情评分。D09 确认清单默认开关、生活补记存储类型及纠正方式前，不默认把一次点击转换为领奖事件；已记项目允许回看/修改，跳过不扣分。与主动周期计划分区展示。

## 6. 计划与目标行动（P3）

### 6.1 日程、当天列表与进度

计划来自用户主动创建，日记一句“想跑步”不自动建计划。创建去掉必填行动领域，不换名字后继续强迫用户选择一个属性；实际影响可涉及多个维度。

支持每天、指定星期、从开始日起每隔 N 个本地日；以日期差计算，不用固定 24 小时跨度替代日历。周一训练只在周一显示，周二不堆积周一待记录/未完成；总计划保留启用/停用定义、数量与历史。长期目标没有具体行动时提供安排入口，不凭目标自动造每日任务。

旧 weekly 表示每周 N 次，作为弹性每周目标保留，不能擅自迁成指定周几。none 不变成每日任务。变更日程/停用仅影响生效后的安排；已有当次结果、目标和规则快照保留。未来生效策略/跨日补录按 D07 定案。

唯一当次身份至少为 `(user_id, plan_id, scheduled_local_date, occurrence_index)`，首版若不支持同日多次则序号固定且不开放重复创建。当日查询只读计算应到期内容，不靠 GET 造事件、发奖或调模型。

### 6.2 结果、分析与结算是三种状态

```text
待记录 → 完成/部分完成 → 保存实际内容 → 分析建议 → 确认入账
待记录 → 未完成待确认 → 卡片内确认 → 未完成·已确认（锁定，无账目）
```

- 完成/部分完成先存事实，再展示属性/金币建议，用户再次确认才结算；无模型也能保存事实，待分析不能伪装成已入账。
- 部分完成填写实际内容/数量，不默认 50% 或 0.5 次；未给数量时保留状态，D07 未定前不新增自动目标百分比算法。
- 未完成在原卡片确认，不弹补充页/成功 toast，不反复解释扣分规则；不造事件、不增加记录日、不调模型、不扣金币/属性，也不调用长期目标失败结算。
- 未操作仍为待记录，不因过期自动改未完成或扣分。
- 最终确认后收起直接切换按钮，服务端拒绝直接把未完成改成完成；纠错是显式版本化更正，保留原记录。已入账纠错沿用实际流水冲正规则，不能静默覆盖旧账，不能借修正推翻“金币撤销不退”的既有规则。

### 6.3 事实关联与入账

可以主动选择本人已有事件作为本次行动事实，或保存一次新事实。模型仅建议关联；先看是否已结算。未入账编辑更新同一次事实/版本，不每点击一次新增 Event。

同一实际行动通过计划、事件、日记再次出现时，只共享事实关联与进度，不发第二份行动属性/金币。技术上同时约束当次安排、事实结算身份、规则版本和 UUID 回执；换请求 UUID 也不能绕过同一当次唯一性。

确认事务遵守既有锁顺序：本人 profile → 当次/事实/判定 → 属性/余额。核对归属、预期版本、判定有效性、配置/主线/规则快照、是否已结算后，同一事务写当次状态、属性流水、金币流水、审计与回执；任一必需写入失败全部回滚。模型调用放事务外，写回再校验。

新主线金额未确认时，不启用 Demo 额外奖励。能沿用既有有效判定确认协议的基础闭环可先交付；依赖新金额的路径关闭并标明暂未启用，不假造免费固定打卡奖励。

## 7. 主线经济、统计与成就

### 7.1 主线金币（方向已确认，D05 阻断新增结算）

金币向当前主线相关的有效投入/成果倾斜；不是所有行动固定加相同币，也不是按“一下午”机械等价计奖。属性仍依据实际行动，不因为目标是考研就额外放大智力。

方案采用可版本化规则表：基础金额、档位条件、主线额外金额、单事实/每日上限、与挑战/连续/成就叠加、主线切换生效点。金额/上限均待确认；先展示有效事实和档位依据，禁止模型自由决定金币或复制 Demo +2/+3/+5。

考研主线下，有明确练习/复盘/成果的学习与同等证据的非主线运动有主线额外金币差别；切运动主线后相反。恢复性活动仍按自身实际价值保留基础规则，不因不是主线变成惩罚。目标关联须明确；一次行动不因关联多个目标叠发多份主线奖励。旧账不追溯重算。

### 7.2 两类记录天数（D01/D02 收束后启用新指标）

事件、日记分别提供累计记录日、当前连续、历史最长连续；条数/篇数另算，同日五条事件只计事件一天。纯问答、跳过、未完成状态、仅打开页面不计原文记录日。

日期事实保留内容所属日、实际首次保存时间和时区，统计实现使用明确规则版本。补记究竟算内容覆盖日还是当时实际坚持书写日、当前段是否可从昨天起算、撤销/删除如何影响指标与已领成就均见 D01；未定前不得展示未标注的“坚持”值或发新奖励。

新旧指标并存过渡，不能把旧累计“篇”更名成“天”而沿用数字，也不为重新分类回收/追加旧币。统计可在临时样本按两种候选口径测试，正式选择后才切展示和奖励读取者。

### 7.3 固定与动态成就（D08 通过后扩展）

现有目录已包含连续日记 30 天，应优先命中固定项；目录外 AI 发现是扩展而非重写固定系统。程序核实指标、阈值、范围、来源/版本，AI 只能提供名称、说明、证据建议，不从文本猜天数或随意发币。

候选流程为发现 → 核实 → 待领取 → 用户确认 → 一次授奖；是否自动点亮徽章、金额/上限/叠加由 D08 决定。语义唯一身份用本人＋指标＋阈值＋范围/规则身份，固定/动态共同核查，“30 天/一个月”换名不能领奖两次。旧 discovered 固定 50 币不是新里程碑定价。

无模型仍有确定统计；不因每次进入成长页付费重新发现。新增动态任务须受用户主动调用/授权预算控制。证据已变、双设备领取、领取与撤销竞争均须锁与唯一约束，不允许 GET 发新奖励。

## 8. 本地导出（P4）

明确区分可读记录、结构化个人存档和服务器数据库备份。现有 JSON format_version=3 含本人金币、属性、成就、券等表，不是只有事件；CSV 仅事件表，也不是全量恢复文件。

| 格式 | 用途及内容 | 实施要求 |
| --- | --- | --- |
| Markdown | 事件/日记原文、日期，可选 AI 完整辅助记录 | UTF-8，可本地编辑；按选中范围组织，默认组合 D10 决定 |
| 离线 HTML | 本地浏览器阅读同样内容 | 单文件可离线读，无外部脚本/字体/追踪请求；正文转义，不能执行记录中 HTML |
| JSON | 可版本化结构化个人存档；记录/问答关联，可选游戏数据 | 保留 v3 兼容或明确升级版本；新增实体纳入归属过滤/引用，不直接破坏旧 importer |
| CSV | 扁平事件/日记列表，字段说明清楚 | 不声称含完整会话/金币账本；防公式注入及中文乱码，正确引号/换行处理 |

导出 UI 提供日期范围、事件/日记、是否带 AI 辅助、JSON 是否带游戏数据等明确选择。默认格式/范围按 D10 决定，不私自将现有 JSON 默认改成 ZIP；ZIP/PDF/附件不是本轮已确认交付项。

选择带辅助内容时，原文、确切 AI 问题、我的回答、跳过/未回答状态、AI 分析分别标角色/时间/来源；保留分析依据版本，不能输出脱离问题的一串回答或把模型文本标作原文。

所有导出只含本人可见业务数据，不含 Key、密码/哈希、恢复/验证令牌、Session/CSRF、租约等秘密；Settings 走白名单，不因新表通用序列化泄密。文件名/path 安全、HTML 转义、CSV 公式防护与中文长文本有测试。撤销/版本历史默认选择见 D01/D10，不因界面没显示就物理删除存档。

日期范围在用户明确时区中计算，导出包含生成时间/规则版本。大数据控制查询与内存，不为“导出全部”无界加载私有全文。新导出不承诺反向恢复；若 JSON schema 改动，现有导入器必须明确支持或拒绝新版本，并提供映射/试迁移计划。

## 9. 账号与独立管理工作区（P5）

### 9.1 注册、邮箱找回与主动改密

产品方向：普通用户可直接注册，不以邀请码为必要条件；保留站点注册开关。邀请旧账号不受影响，不因移除邀请入口让现有 owner/user 失效。不能只删前端邀请码而后台仍要求 `invite_token`。

邮箱绑定/验证/找回是候选首选路径，手机号、QQ、微信另期接入。是否必填/未验证能做什么、旧账号绑定过渡与邮件服务见 D04；这些未定前可建隔离验证骨架，不能开通真实邮箱注册或声称邮件已发。

正式邮箱路径必须验证实际持有权；未知邮箱的找回提示统一，不泄露账号存在与否。恢复令牌随机、仅摘要入库、单次/有有效期、限流；有效期/限流技术值由 Writer 给出配置和理由，不能无期限。换绑保护旧邮箱/新邮箱验证状态和当前身份，冲突不接管他人账号。密码与令牌不进日志/导出。

登录后“账号与安全”提供当前密码＋新密码的主动改密；找回流程不要求遗失的旧密码。改密/找回成功与会话撤销同事务，对当前/其他设备的退出策略按 D04 明确；至少防旧并发登录在撤销后遗留有效会话。保留既有 Origin/CSRF、密码哈希及账号锁保护。

旧恢复码过渡按 D04 保留或逐步退出，不突然删除现有唯一恢复途径。测试只用假 SMTP/受控测试收件箱；未授权不向真实用户发邮件。

### 9.2 管理范围候选（D11 确认后实施该范围）

管理端与日常账号页面分开，推荐复用登录页，以服务端角色进入工作区；无需另写一套认证系统。复用已有 `role=owner/user` 并明确能力映射，不因 Demo 名为 admin 就批量更改 owner 角色或给普通账号授权。

| 页面 | 首批候选能力 | 权限边界 |
| --- | --- | --- |
| 管理概览 | 普通账号总数、正常/停用数、今日新增、近 7 日登录、管理账号数 | 普通与管理计数分开；采用服务端时区/日期口径，样例 4/1 不能硬编码 |
| 用户账号 | 用户名查找、状态/角色筛选、创建/最近登录、邮箱验证状态、停用/恢复 | 不浏览他人日记、模型 Key，不修改他人金币/属性；停用原因/确认/审计 |
| 公告 | 编辑、预览、发布、撤下 | 发布持久化与展示版本一致；不等于自动发邮件/短信/微信通知 |
| 站点设置 | 站点名称/说明、注册开关；默认 AI 配置单独受 D06 控制 | 无预算/服务不开通默认 AI，不能与个人模型配置混写 |
| 操作记录 | 管理人、时间、对象、动作、原因、变更版本 | 不含用户原文、私密问答、密码/Key/令牌；分页、只读 |

管理账号安全有自己的改密/退出与返回入口；刷新/直接路由落到合法管理页，不渲染普通日记。开发角色切换按钮不进入生产。若同一人另有日常账号，通过正常认证切换，不靠本地存储改 role。

所有管理接口服务端校验管理能力；普通用户直调拒绝且无副作用。不能停用当前唯一可用管理账号；停用普通账号需撤销其会话，并规定在途任务不能继续发布结果/结算。恢复只恢复使用资格，不重放历史账目。重复管理请求有版本/回执，跨标签冲突反馈明确。

本轮不加管理员任意改账、代读日记、假扮用户、硬删除账号、批量清库或自助提权。默认 AI 上线后的用量/预算监控按第 4.3 节另加，不先做无数据的复杂运营看板。

## 11. 数据模型、API 与安全实现约束

以下命名为建议，Writer 可在等价约束下调整，但必须在交付记录给出最终 schema/API 与映射，不能同时落两套同义账本。

关键写入合约：创建/最终确认带 `request_id`；修改/回答/关联带目标资源 ID 与 `expected_version`，回答另带 `question_id`。重复创建/确认同请求同正文回放原回执，旧版本/异正文冲突返回 409，保留前端输入；当前用户由 Session 解析，不能信任正文传入的 user_id。候选接口名称可以调整，上述归属、版本与幂等语义不可省略。

| 增量 | 最少持久内容/约束 | API 方向 |
| --- | --- | --- |
| 记录类型/日期 | kind、local_date/timezone、时间精度、原来源、内容版本；旧值兼容 | 扩展现有 events 及列表类型过滤；新日记按显式类型保存 |
| 回顾 Session/Turn/Analysis | 本人/日/来源快照、问题 ID/顺序/角色/状态、回答版本、模型/任务版本；轮次唯一 | 新 `/api/review-sessions` 创建/继续、questions、answers、skip/end 及分析任务；保留旧 daily-reviews 可读 |
| 日程/当次计划 | 日程类型/参数/生效版本，唯一当次键、结果版本/锁定、事实关联及结算身份 | 扩展 items；新增只读今日查询、结果保存/确认/显式更正，分析复用 analysis-jobs |
| 事实关系 | 候选来源版本、用户确认/拒绝、fact ID、结算唯一身份 | 关联/拒绝为显式写操作，非 GET 副作用 |
| 模型验证/来源 | provider/model/group/配置版本、验证时间/状态、受控错误；站点与个人作用域分开 | 扩展 llm-config/test，不把 Key 明文纳入摘要 |
| 账号/邮件 | 验证后邮箱归属、令牌摘要/用途/过期/消费、会话撤销、最近登录 | 扩展 auth 注册；新增邮箱验证/找回/改密/换绑，统一认证与限流 |
| 管理 | 公告版本、站点设置版本、操作记录/管理角色与目标 | `/api/admin/*` 管理守卫及分页，具体路径在 P5 合约中给出 |
| 主线/规则/统计 | 目标关联、主线/规则快照，指标身份和日期口径版本 | 单独能力开关，金额/指标待定前不启用新结算 |
| 导出 | schema 版本、选择范围、所有新实体的本人归属和引用 | 扩展 `/api/export` 格式/筛选，支持明确的旧 v3 兼容策略 |

所有受保护的新表有本人归属，外键/多态引用同时校验。跨用户资源访问延续 404/不可见策略，未认证保持 401，管理能力不足拒绝。旧业务 User/Session 归属过滤不因后台模块而绕开。

需要新 Alembic revision；不修改已执行 a001/a002/b003/b004，不用 cloud 自动建表，不把 SQLite migrate_schema 代替 PG 迁移。迁移允许为空的兼容列先部署，回填只用确定映射，唯一约束/索引与冲突策略在独立 PG 验证；不要直接跑真实库。新增导出表、导入引用白名单、任务归属和读写协议需同步盘点。

财务与最终状态写入必须保持请求 UUID/输入指纹/回执、资源版本、同事实唯一性、事务/锁。请求重放相同正文返回原结果，异正文 409；GET 不触发结算。模型调用无长事务，有超时/预算/租约，写回检查内容/配置/停用/任务版本，防取消和改钥后的迟到结果。

已有未回源的 PG 初始化密码换行缺陷独立修正：`deploy/init-app-role.sql` 当前 `trim(pg_read_file(...))` 不能可靠去掉换行；改为明确剥离空格/tab/CR/LF并按约定校验秘密格式，保持 SQL 动态 literal 安全及无秘密日志。仅影响新空库初始化，已有库不自动改密码、不删卷重建。用临时秘密/隔离 PG 验证，不复制截图中的现场 ALTER ROLE 操作到常规升级。
