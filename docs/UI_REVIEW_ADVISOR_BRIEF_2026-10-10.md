## 1. 审查结论

当前 UI 已经清爽、可辨认，四个主入口和手机底部导航的方向合适，适合作为继续打磨的基础。但还没有达到精致、统一、适合长期手机使用的状态。最大的缺口是信息密度、控件布局、图表适配和文字可读性。

U04 的阈值依据为 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。本次只测了指定颜色组合，不能据此宣称整个站点已完成无障碍审计。

另外两项需顾问先核实数据语义，再决定是否随本轮小范围修正：

1. 首页记录状态目前主要根据 `analysis_intent` 显示「可稍后处理」，手账列表多数显示「可查看分析」，不一定准确表达已完成、待确认等状态。不得为了漂亮自行猜状态；核实已有接口可提供的真实状态。如需新增查询接口，单列范围、成本和验收，不默认纳入纯 UI 改动。
2. 手账列表的「旧纯享记录」筛选是 `is_pure`，不能直接改名为「不分析」，因为它与 `analysis_intent=never` 并非同一字段含义。「继续回看」是否到达末页也需按接口实际返回判断，不能假造总页数。

## 5. 建议的视觉方向与设计参数

### 5.1 一条明确方向

「安静的生活手账，带一点成长游戏的趣味」：文字是主角，日期是线索，记录能快速写下、连续回看，成长信息作为可探索的第二层。

建议沿用当前浅色和蓝色品牌基础，减少重复的大标语与装饰性说明。做一个有辨识度的小细节即可，例如日期旁的页签、保存后的短暂勾选反馈，或与已有记录对应的活动格。不要为每个区块增加插画、大数字、阴影和口号。

### 5.2 推荐起点，顾问需验证后定稿

| 项目 | 建议 |
|---|---|
| 基础配色 | 页面 `#F6F7FB`、纸面 `#FFFFFF`、正文 `#2B2F3A`、次级文字候选 `#62697A`、主色候选 `#4058D6`、浅主色 `#EEF1FE` |
| 语义颜色 | 危险、警告、成功单独定义 token；旧规则红涨绿跌的业务表达继续保留，危险按钮不要复用「增长」变量。所有状态同时提供文字或图标解释 |
| 中文字体 | 优先可靠的本地系统中文无衬线字体，检查 Windows、Android、iOS 的实际回退与图表字体一致性。不把外部字体 CDN 作为正常使用依赖 |
| 字号层级 | 手机正文/输入 16px；列表标题 17–18px；次级信息 13–14px；手机页标题 24–26px；桌面页标题可到 30–32px。记录摘要宜至少 15px，依实际密度定稿 |
| 行高 | 正文约 1.7–1.8；标题约 1.35–1.45；元信息约 1.5。长正文与列表摘要分别设置 |
| 间距 | 4、8、12、16、24、32px；手机边距 16px，正文卡片内边距 16–20px。优先减少无效层级，不用极小字号硬塞内容 |
| 宽度 | 桌面阅读区建议约 720–820px，图表区可更宽；宽屏不强求把长正文铺满全部可用宽度。768–1024px 另验侧栏与内容空间，不机械照搬桌面 |
| 形状 | 输入/按钮约 8px，普通卡片 12px，核心录入卡 16px；阴影只用于必要层级，不给每条记录加同样厚重的卡片 |
| 触达 | 常用点击区域按至少 44×44px 设计；文字链接提供足够点击内边距，底栏考虑安全区。44px 是本项目舒适目标，不应误写为 WCAG 2.2 AA 的统一最低要求 |
| 动效 | 仅在用户操作后给出简短状态反馈，可从 150–200ms 起试；尊重 `prefers-reduced-motion`。不为这轮加入 GSAP、3D 或持续循环动画 |

触达标准区别可参考 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：该 AA 条目通常以 24 CSS px 及相应例外描述。顾问必须把项目设计目标与规范条款区分开。

## 8. 实施分批与验收建议

### 第一批：修复密度与基础可读性

处理 U01–U04、U06 的通用布局原因：记录预览、移动成长布局、趋势选择、对比度、搜索和登录操作。确定 token 与作用域，避免全局改 `.row` 一次影响所有历史表单。

验收示例：

- 在 390×844、360×800 的默认字体下，使用本次同长度样本，手账标题最多两行、摘要最多三行；日期不再侵占正文左列。390px 下首条记录目标约 220px 以内；字体放大时优先可读，不强制固定高度。
- 390px 成长页能力区域单列，数值和标签不相互挤压；趋势维度选择不再纵列 13 个按钮。所有维度仍可访问，不修改数值、曲线数据及业务默认选择。
- 桌面搜索按钮宽度由内容和点击目标决定，与输入框垂直对齐，不占三分之一搜索区。
- 登录页只存在一个主提交动作，次级模式当前状态清楚，找回和邀请入口可用。
- 普通可用文字的实际前景/背景对比度至少 4.5:1；状态、禁用等按适用规则检查。检查图表硬编码颜色，不能只改 CSS 变量。

### 第二批：打磨主要使用流程

处理 U05、U08，统一今天、详情、待处理与睡前回顾。默认 390×844、键盘未打开、没有错误/扩展信息时，保存按钮、待处理和睡前回顾两个入口均完整出现在底栏上方。此目标只适用于定义的默认场景，200% 文字或键盘打开时应允许正常滚动，不靠压小字体达成。

必须核验这些受保护行为：

- 账号内草稿恢复，切页/刷新不丢；账号切换不串稿。
- 保存结果不明时沿用同一个请求回执重试，不因重排/重新挂载生成新回执。
- 原文持久化成功与分析提交成功分开反馈，不能把模型失败显示成记录丢失。
- 「不分析 / 稍后处理 / 立即分析」意图沿用，默认值不悄悄变更；页面打开、展开选项不调用付费模型。
- 已确认记录的冻结、复核规则、挑战关联、删除回滚与金币保留说明继续生效。
- 回顾引用原记录，结束回顾不重复结算；冲突时旧输入可保留，新旧版本可比较。

### 第三批：统一旧页面与细节

处理 U07、U09、U10，统一我的、设置、旧页面入口、图标、空状态、错误和焦点。不能只精修四个首页，让点入后的角色、目标、挑战、商店、锚点和判定页面继续出现明显样式冲突；顾问可以按文件拆小批，但需说明完整覆盖范围。

设置页常用模型/数据操作应易于定位，停用模块不能伪装成可操作；导出和云备份必须仍清楚区分；密钥不回显。重要费用说明不能只放在默认折叠、用户操作前看不到的位置。

### 最终验证与交付

- 视口：360、390、768、1024、1440px；至少覆盖手机和桌面两套结构。页面无整体水平溢出，长英文/网址/无空格内容可换行。
- 内容：空数据、短记录、长标题、2 万字符正文、同日多条、中文混英文、无模型、处理中、待补充、待确认、已确认、失败、保存结果不明、回顾版本冲突。样本必须虚构。
- 可访问性：键盘 Tab 顺序、焦点可见、不只靠颜色、标签和错误关联、200% 文字、减少动画、最后一条内容可滚到固定导航上方。输入的 `:focus` 与 `:focus-visible` 需检查选择器覆盖，不能仅加一条全局规则就宣称完成。
- 真机：至少一台本人实际使用的手机检查键盘弹起/收起、时间选择、底部安全区与返回。若只有模拟浏览器，明确写未完成真机验证，不写全通过。
- 图表：布局/折叠改变后调用正确的 resize；隐藏容器不能初始化出零宽图；提供可读的数值或文字替代。没有数据时不生成虚假趋势。
- 检查：前端生产构建；根据实际改动运行现有前端行为检查及受影响回归。不要为纯配色写镜像 CSS 的测试，但保存回执、草稿、账号、冲突和关键操作若受影响必须做有意义的验证。所有测试隔离真实库和模型。
- 交付：更新后的界面、实际检查结果、同视口前后截图、未通过项，以及 `docs/UI_POLISH_DELIVERY.md`。不把模拟截图当作真实云部署或真实业务验收。
