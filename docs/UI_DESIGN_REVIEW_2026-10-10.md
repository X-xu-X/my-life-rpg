## 4. 必须补足的实施约束

### R01 / P1：设置定位不能清空未保存输入

**性质：设计实施风险，未在当前页面复现丢稿。** [App.vue 第 37 行](C:/Users/19687/Desktop/游戏人生/work_place/my-life-rpg/frontend/src/App.vue:37) 的 RouterView key 包含 `account.id + ':' + route.fullPath`。原方案允许用 route hash 或 query 定位设置区块；如果在已经打开的设置页更改这些值，会改变组件 key 并重建页面。设置模型表单的未提交模型名、供应商和临时 Key 不会因使用 details 自动得到保护。

本轮确定采用原方案允许的简单路径：我的分组入口统一进入 `/settings`，设置页顶部目录使用 `type="button"` 在当前页面展开并滚动到区块，不修改 URL hash/query。不要为此删除账号隔离 key 或重构全局路由。区块标题可用 `tabindex="-1"` 承接主动定位的焦点，确保不会滚到固定底栏下面。

验收：填写虚构的未保存配置，连续点击目录、开合折叠与跨布局宽度，输入和组件实例保留，且没有额外保存/测试请求。若确需深链接，另交完整的同页状态保留方案，不能只加 scrollBehavior。

### R02 / P1：加载、失败与真实空态逐页落实

**性质：当前源码可确认的呈现缺口，未执行网络故障注入。** [HomeView.vue 第 11 行](C:/Users/19687/Desktop/游戏人生/work_place/my-life-rpg/frontend/src/components/HomeView.vue:11) 将记录和待处理一起读取，初值为空/0，缺少明确的初次加载状态；[AttributePanel.vue 第 35 行](C:/Users/19687/Desktop/游戏人生/work_place/my-life-rpg/frontend/src/components/AttributePanel.vue:35) 主要读取 Promise.all，mounted 调用缺少页面级 catch/loading；[RecordList.vue 第 23 行](C:/Users/19687/Desktop/游戏人生/work_place/my-life-rpg/frontend/src/components/RecordList.vue:23) 的空提示未排除 error。

按页面显式区分「读取中 / 首次读取失败 / 成功且为空 / 已有数据刷新失败」。只在成功读取后显示确定的 0 条、暂无记录、无历史或基线状态。首页读取失败不能阻止录入表单继续按现有接口保存；刷新失败保留上次可用内容并标记未刷新成功。错误重试只能重新读取，不能调用模型或重放写入。

允许为 UI 添加最少的 loading/error/loaded 状态和读取异常处理，不新增后端接口、不重写数据口径。分页、待处理轮询和历史回顾也按同一状态原则检查。

### R03 / P2：搜索布局与键盘顺序一致

**性质：原方案布局之间的实施冲突。** 当前 [RecordList.vue 第 21 行](C:/Users/19687/Desktop/游戏人生/work_place/my-life-rpg/frontend/src/components/RecordList.vue:21) 的 DOM 是输入→筛选→搜索；原方案手机视觉是输入＋搜索→筛选，桌面又是输入→筛选→搜索。如果仅用 grid/order 重排，手机焦点可能在两行之间往返。

定稿为 DOM 与视觉均「输入→搜索按钮→筛选」：手机第一行输入＋搜索、第二行筛选；桌面同一行输入＋搜索＋筛选。桌面列可为 `minmax(0,1fr) auto 160px`。保留 Enter 提交和筛选 change 刷新，不用正数 tabindex 修补顺序。此处替代原方案 3.2 的桌面三列顺序。

### R04 / P1：图表并排取决于内容空间，折叠不能重置选择

**性质：设计宽度预算风险，未完成 1024px 新截图验证。** 原方案在 ≥1024px 使用桌面侧栏，又同时要求能力/雷达并排。按外边距 64px、侧栏 184px、间距 32px，1024px 下正文预算约 744px；雷达仍可能分到过窄的区域。

保持 1024px 桌面壳层断点；能力/雷达区域可用宽度至少 860px 才并排，否则继续单列。简单实现可把并排视口断点推到 1200px，并实测内部宽度；不要求引入新布局库。新增 1200px 和 1023/1024px 边界验收。

雷达默认手机收起、宽桌面展开，但用户手动开合不应被每次 resize 覆盖。趋势 select 与按钮共用现有 growthDim，不因切断点恢复最低维度。关闭的 details 内不初始化零尺寸图；展开后 nextTick 并在容器非零尺寸时 init/resize。真实数值列表始终可读，不靠强制横向滚动承载雷达。

### R05 / P2：品牌统一保留中文主名

用户已倾向保留「游戏人生」，并采用英文标识 LifeXP。更新可见品牌、登录品牌、浏览器 title；空间不足时只显示中文主名。原「一页一日」可作为次级说明，不再作为与产品名竞争的另一品牌。

只统一用户可见文字。仓库、API、Cookie、账号草稿 key、部署项目名和历史报告来源不改。不要虚构备案号、域名购买状态，也不要为本轮添加域名管理界面。

### R06 / P2：前后截图必须有可复现的样本

现有 evidence.json 记录了几何、请求与颜色，但不能据此重建所有虚构记录和响应。当前 `_tmp_ui_server.py` 会启动后端并写入本地 QA 数据库，是另一种旧验收工具，不能当成本次「全部 API mock、无后端」截图的独立复现脚本。

Writer 应随本轮截图交付虚构 fixture、运行步骤、实际浏览器版本/字体/缩放/视口和 API 覆盖记录。能找到旧样本则复用；找不到时，在修改 UI 前用一套固定新样本重拍 before，之后同样本拍 after。不能以不同长短的记录证明高度改善，不能覆盖旧截图来隐藏缺失。

## 5. 颜色复算与可访问性边界

本轮用 sRGB 相对亮度公式独立复算，下列结果与原方案相符；没有对实际页面所有状态进行审计。

| 前景 / 背景 | 比值，显示取三位 |
|---|---:|
| 旧次级 `#7A7F8C` / 白底 | 4.006:1 |
| 旧次级 `#7A7F8C` / `#F6F7FB` | 3.742:1 |
| 旧主色 `#4F6EF7` / 白底 | 4.281:1 |
| 新次级 `#62697A` / 白底 | 5.496:1 |

| 新控件边界 `#7E8798` / 白底 | 3.617:1 |

验收使用未舍入的值。普通文字目标至少 4.5:1，实际透明度、悬停、图表颜色和背景另算；不能用这张表替代页面检查。44px 为项目舒适触达目标，不冒称 WCAG AA 的统一最低尺寸。200% 文字下允许滚动与首屏布局改变，要求功能和信息保留。

依据：[W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[焦点顺序](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)、[文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
