## 核心设计理念：AI 是「引导者」，但科学客观是底线

- **AI 的定位是「引导者」**：加点、提醒、复盘、建议等所有功能，本质上都是引导一个人走向更好，而非冷冰冰的打分/裁判。
- **但引导 ≠ 迎合**：温和的是「语气」，科学客观是「底线」——加点严格依据量化锚点库与科学标准，客观如实、不迎合、不夸大。两者缺一不可。
- 落地原则：①科学客观为底线（加点/判定严格依据锚点库，该提醒如实提醒）；②语气温和（该鼓励真诚鼓励，但不因引导而放松标准）；③引导优先于量化（如日记追问核心是帮用户回忆复盘，加点其次）；④建议要可执行。
- 已对齐：judge（成长引导者定位 + 科学客观底线）、report（成长顾问）、追问（回忆复盘优先）。待对齐：onboarding（已是向导）、未来新增的提醒/桌宠等模块，需延续此定位。

## M1 决策

### D1：单用户模型但表结构预留多用户
- 背景：PRD 定位 V1 为"本人个人自用"，但数据模型要求 `users` 表并预留多用户。
- 决策：保留 `users` 表，V1 启动时自动创建一条默认用户（`username=default`），所有 API 默认操作该用户；外键全部关联 `user_id`，为 M4 多用户铺路。
- 影响：API 不强制传 user_id，服务层内部固定解析到默认用户。

### D2：建表方式双轨
- 背景：PRD 要求"建表 SQL 随 M1 交付"，同时要求 `uvicorn app.main:app --reload` 本地可跑。
- 决策：同时交付 ①`sql/schema.sql`（可读文档、供 MySQL 迁移）②`Base.metadata.create_all`（启动自动建表）。两者字段保持一致。

### D3：LLM 失败降级
- 背景：判定依赖 DeepSeek，无密钥或网络异常时不应让应用崩溃。
- 决策：`llm_service` 在未配置密钥时抛出明确异常；判定接口返回 503 并提示"请先配置 DEEPSEEK_API_KEY"。V1 不做本地规则引擎兜底（避免口径不一致）。

### D4：锚点单次增减区间
- 背景：PRD 4.4 要求"单次增减建议在合理区间（如 -5 ~ +5）"。
- 决策：判定结果校验时，单属性 delta 绝对值上限 5，超限由服务层钳制并记录，防止模型输出异常值污染数据。

### D5：属性维度定义
- 背景：Onboarding 需生成初始属性面板，属性名称需稳定（便于后续判定命中）。
- 决策：内置 6 个标准属性——体能、智力、情商、创造力、规划力、健康（对应 PRD 3 节"属性"示例），允许用户在校准/异议时补充，但 V1 判定只作用于这 6 个。

### D6：经验值/等级（游戏化）归属
- 背景：等级/经验属 M2~M3 游戏化内容，但 PRD 6.3 数据模型未单列 level 表。
- 决策：等级与经验在 M1 不实现，字段预留到 `user_profiles`（`level`/`exp`），M2 补曲线逻辑。TODO 见代码注释。
