## 1. 任务方式

用户希望 P2～P6 一次交给 Writer 连续实施。本任务提供统一续作入口：按依赖分阶段完成后端、真实 Vue 界面、迁移、兼容、测试与交付，阶段通过后继续下一阶段，不要求用户逐批回复“继续”。不要停在 Demo、静态表单、假接口或只建框架。

依据 [开发总计划](TRIAL_FIX_DEV_PLAN_2026-10-16.md)、[原任务书](WRITER_TRIAL_FIX_2026-10-16.md)、[P1 复核](TRIAL_P1_REVIEW_2026-10-16.md)及用户已确认流程。本文件补充连续执行方式，不替用户决定尚未选定的真实模型、运营预算和游戏奖励金额。

常规代码结构、组件拆分、等价 API 命名、索引、错误处理等技术细节由 Writer 自行完成；遇一个待定策略只隔离对应路径，继续其他独立工作。集中报告确实影响正式启用的选择，不把所有技术问题退回用户。

## 3. 未决策略如何实现，而非停掉整个任务

[总计划 D01～D11](TRIAL_FIX_DEV_PLAN_2026-10-16.md)仍记录产品选择。实现者须把策略与数据事实分开，使已确认功能可以使用，未确认部分可在以后配置，不要求现在猜所有答案。

- **日期与旧分类**：保留内容所属日、实际保存时间、时区和旧来源。分别计算、清楚命名内容覆盖与保存日指标；未选择正式“坚持”口径时不将候选指标用于新增奖励。旧分类未知明确保留。
- **同事实与计划进度**：用户显式关联、候选确认/拒绝、事实唯一身份与版本先完整实现；未定的新增成果差额结算和百分比策略独立关闭，不能用它们阻止保存结果/查历史。
- **主线金币**：实现版本化规则表、档位条件/金额/上限/叠加、事实与主线快照、预览与原子确认。无经确认规则表时不新增主线币，原经济协议继续可用；仅合成测试使用明确标记的测试规则。
- **默认 AI**：实现独立服务端配置/秘密引用、主动选择、用途解析、版本校验、配额/预算、停用/错误/监控。真实供应商/模型/费用与个人日额度未确定时保持“未开通”，自配和关闭仍可用。不要写死 Demo 的 Xing4.0 为正式默认。
- **动态成就**：完整实现证据核实、待领取、忽略、防重与规则控制。未定奖励的候选可以显示，不能用旧发现型 50 币或任意模型数字自动结算。
- **账号/管理**：完整实现可配置注册/验证策略、旧账号绑定过渡及管理五区；测试可覆盖不同策略。未选择邮箱强制门槛/会话策略时保持兼容、不突然锁旧用户。真实邮件服务未配置必须明确不可发送，测试发件不能混作生产发件。
- **清单/导出**：清单关闭/跳过/补记与引用可用，无默认领奖副作用；导出可明确选择格式/范围，默认沿用旧 JSON，不为等待最终默认组合而不交付可读格式。

测试策略与界面候选不代表正式产品规则已确认。交付必须列出哪些已可用、哪些等待配置/选择、哪些因环境未验收，不能把关闭/未实现混称完成。

## 4. 验证、提交与不停工原则

1. 复用已有归属/Session、业务写协议、profile 锁、UUID/输入指纹/版本/回执和模型租约；新当次/事实/成就用数据库唯一约束，不能只禁用按钮。
2. 新 Alembic revision，不改已执行 revision、不删库/卷、不碰真实旧库。升级/导出/importer 映射或拒绝策略同步说明。
3. 每阶段做针对性后端/前端回归与构建，再检查关键真实 Vue 交互和桌面/手机布局。P2 的完整问答、P3 的重复结算、P5 的权限和 P6 的预算不可仅用截图验收。
4. 独立 PG、真实模型/邮件与实机缺环境就登记 NOT_RUN，继续能做的代码/隔离验证；这些发布门槛保持未通过，不伪造结果、不在生产试错。
5. 按逻辑单元中文提交并更新交付记录，通过本阶段必要检查后直接进入下一阶段。反复的已通过全套测试不代替后续实施。
6. 总交付提供阶段/功能矩阵、最终数据/API合约、测试与关键截图、未启用配置/决策清单、迁移与回退步骤。用户可整体审查，不需要再次一页页提供所有截图。

此任务包含本地实现与验证，不自动包括 push、云包发布、真实部署/迁移、真实通知、默认模型充值/启用或清理测试数据。当前只准备任务书，没有通过工具发送到既有 Writer 聊天；将本文交给 Writer 后即可作为一个连续任务执行。
