## 2. 最终视觉规则

### 2.1 颜色 token

以下为本轮实现默认值，不必再问用户选择颜色。保留当前蓝色基础，用更深的文字和品牌色改善阅读；小面积色块和日期编排提供辨识度，不增加大面积渐变、插画、玻璃效果或持续动画。

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#F6F7FB` | 页面背景 |
| `--card` | `#FFFFFF` | 表单与内容纸面 |
| `--surface-subtle` | `#FAFBFE` | 分析区、次要背景 |
| `--text` | `#2B2F3A` | 正文、标题 |
| `--text-sub` | `#62697A` | 辅助信息、元数据、占位提示 |

| `--primary-soft` | `#EEF1FE` | 选中导航、非危险强调底色 |
| `--border` | `#E6E8EF` | 非交互分隔线、卡片边界 |
| `--control-border` | `#7E8798` | 可编辑输入、原生选择器、次按钮边界 |
| `--success` / `--success-soft` | `#267247` / `#EEF8F1` | 保存成功、完成提示 |

| `--positive` / `--negative` | `#B9382B` / `#187247` | 保留旧规则红涨绿跌；必须同时显示正负号/文字 |

| 项目 | 实现值 |

| 摘要 | 15px / 1.7，最多三行；不把 2 万字正文直接全部放进预览 DOM |

| 点击目标 | 常用动作/链接至少 44px 高；导航每项至少 48px 高；边缘区域不依赖小图标精确点击 |
| 动效 | 颜色/背景过渡 160ms；无持续循环。`prefers-reduced-motion:reduce` 时移除非必要过渡和滚动动画 |
| 0–759px | 单列内容，手机页头+底部四导航，边距 16px |
| 760–1023px | 单列内容，仍使用手机导航以保留平板阅读宽度；边距 24px，内容居中，最大 820px |
| ≥1024px | 桌面侧栏 184px，列间距 32px，内容列 `minmax(0,1fr)`；外层最大 1280px，左右各 32px |
| 阅读宽度 | 手账、今天、详情、回顾内容最大 820px；设置最大 900px；成长最大 1000px；不把长原文横铺整个宽屏 |

移动底栏内容高 64px 加 `env(safe-area-inset-bottom)`，主内容末尾至少保留 `88px + safe-area`。不使用滚动锁。输入聚焦后先保证浏览器能滚动到输入和提交动作，不增加基于 UA 的软键盘猜测逻辑。真机发现底栏遮挡时再做小范围适配，不能未经验证声称解决了 Safari 键盘。

44px 是本项目的舒适触达目标，不是 WCAG 2.2 AA 的统一最低条款；[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 对 AA 条目通常以 24 CSS px 与相应例外描述。

所有 input、textarea、select、button、a、summary 必须有焦点态。删除或改写当前会覆盖焦点的 `input:focus { outline:none }` 等规则，再分别验证 `:focus-visible`；不要只新增一条低优先级规则。错误关联使用 `aria-describedby`/`aria-invalid`，不要把整个页面放进实时播报区域。

### 2.3 按钮、图标和状态

- 同一操作区域最多一个主按钮；辅助动作用普通边框或文字按钮；危险动作独立放在区域底部，红字/浅红底，保留确认步骤。
- 手机表单主按钮铺满该区域宽度；桌面由内容决定宽度，最小高度仍为 44px。加载时保留区域尺寸并修改动作文本，已有防重入与禁用条件原样保留。
- 导航图标使用一套 24×24 的本地 SVG，1.75–2px 笔画、`currentColor`，不要混用 Unicode 和多种图标风格。图标旁有文字时设 `aria-hidden="true"`。纯图标按钮必须有可访问名称和 44px 点击区。
- 当前选中导航继续使用路由 meta 与 `aria-current`，不能靠点击后本地选中状态替代真实路由。移动页头的「一页一日」作为轻量品牌签名，不每个区块再加口号。
- 状态必须有文字。排队/处理中用品牌色，待补充/冲突用警告色，失败用危险色，已确认用成功色，不分析/已保存使用中性色。状态标签不做成会误导为按钮的外观。

首页与列表当前不能可靠只凭 `analysis_intent` 判定已完成/待确认。本轮默认不加接口、不为每条记录请求判定：首页/手账仅显示确定事实「已保存」及「不分析」意图；其余统一给出「查看原文与分析」链接语义。只有待处理和详情已经拿到的真实任务/判定对象才能显示其状态。不得推断「有意图=已分析」或把空缺状态展示成完成。

## 3. 页面布局与交互定稿

### 3.1 今天：先写，再处理

手机默认结构及目标尺寸如下。页头用「今天」作为可识别的主标题，日期使用 `localDate()` 的现有口径。原标语可缩为一行副文案「留下一件小事，也算今天的一页」。不要额外请求模型生成欢迎语。

```text
品牌                    一页一日        48 高
今天                    10 月 10 日
留下一件小事，也算今天的一页              页头总高约 78
┌─────────────────────────────┐
│ 记一下今天发生的事            │
│ [正文输入，至少 128px 高]     │
│ 发生时间：现在    [修改时间]  │
│ 分析 [稍后处理 v]            │
│ 原文先保存，分析由你决定       │
│ 本机草稿 · 尚未云端保存        │
│ [         保存记录         ] │
└─────────────────────────────┘
[待处理 2   去看看] [睡前回顾   留一句]
今日片段                    项目与目标
记录预览……
底部：今天 / 手账 / 成长 / 我的
```

录入卡默认目标约 410px 内、两个后续入口高约 64px，页头与间隔控制在总首屏预算中。390×844 默认字体、键盘关闭、无错误/恢复提示/展开选项时，保存按钮及两个后续入口均完整位于底栏上方。遇到长状态、错误、200% 字体或软键盘时正常增高和滚动，不使用固定卡片高度或隐藏溢出。

时间交互：`occurred` 为空时清楚显示「现在」，保留提交时取时间的现有逻辑，不在打开页面时写死时间。`修改时间` 为 `type="button"`，展开带标签的原生 datetime-local 控件并聚焦；已有补记草稿自动展开。用户填写时间后显示该值；旁边提供「使用现在」按钮清空 `occurred`。清空和选择仍进入现有草稿缓存，不新增另一套时间换算。保存中/结果不明时，所有修改入口与原控件同步禁用。

分析选择始终可见，不折叠成无法辨别当前选择的小图标。原生 select 保留三个值 `later/now/never` 与默认 `later`。选择 now 时在保存按钮上方显示「原文先保存；随后提交分析，供应商可能计费」。仅选择 now 或展开选项不触发模型；提交仍使用现有先保存再分析的逻辑。

草稿/正在保存/结果不明/保存成功/分析失败，均保留独立反馈区域。`uncertain` 状态按钮必须继续写「查询并重试本次保存」，保留原 payload 与回执。确认保存成功后的记录链接可见；不能用 2 秒 toast 替代唯一持久反馈。Composer 不因时间展开或页面布局切换而重新挂载。

桌面：侧栏外内容最大 820px，页头→录入卡→双入口→今日片段；发生时间与分析允许同行两列。录入区仍为主视线，不增加与文本输入竞争的三列仪表盘。原有 `@saved="load"` 刷新关系保留。

### 3.2 手账：日期不挤压正文

```text
手机                             桌面，内容最大 820px
手账                             手账             一行说明
原文一直在这里                    [搜索……][筛选 v][搜索]
[搜索记录…………][搜索]              ─────────────────────
[筛选：全部 v]                    10-10 18:30 · 已保存
10-10 18:30 · 已保存               两行以内的标题
两行以内的记录标题                 三行以内的摘要……
三行以内摘要……                    ─────────────────────
─────────────────                 下一条……
下一条……
[继续回看]
```

搜索栏使用独立 CSS grid。手机第一行 `minmax(0,1fr) auto` 放输入和搜索按钮，第二行筛选占满；桌面三列 `minmax(0,1fr) 160px auto`，对齐控件底部。每项仍有可见标签。搜索按钮约 64–80px 宽，不被 `.row > *` 拉伸；Enter 提交，筛选 change 自动刷新继续保留。

每条记录布局改为元信息→标题→摘要，日期放在正文上方，手机/桌面都不占独立窄列。标题最多两行、摘要最多三行，CSS line-clamp，标题/摘要区域 `min-width:0; overflow-wrap:anywhere`。建议保留当前 240 字符摘要截取作为列表性能边界，再做视觉裁切；不改已保存的原文。全文通过同一个 RouterLink 进入详情，不需要再添加每条「展开」按钮。标题与摘要之间 6px，元信息与标题之间 8px，记录上下内间距各 16px。390px 同样本第一条记录目标 ≤220px；字体放大后允许超过目标高度。

筛选 `pure` 显示「历史纯享记录」，`ordinary` 显示「其他记录」，提示解释「历史纯享标记与当前是否分析是两种设置」。查询仍发送原 `pure:true/false`，不得将其改成 `analysis_intent`。不是本轮要消除的数据历史问题。

分页不伪造总页数。保留现有 cursor 行为；若后续请求返回空数组，可在当前查询上下文显示「已经回看到这里」并隐藏继续按钮，搜索/筛选重置此局部标记。不能凭 `data.length < 某个猜测值` 推断末页。这个小范围变化若实施，应加空批次与重新搜索的行为验证；不新增后端分页契约。

初次加载：页面保留标题和搜索，显示「正在读取记录…」；空数据与空搜索结果文案区分，后者提供清除搜索/筛选动作；追加失败保留已显示记录及同一查询重试，不变成空页面。

### 3.3 成长：数字可读，图表是第二层

旧规则/基线说明                    旧规则/基线说明

子维度候选（有时显示，保持顶部）      子维度候选（有时显示）
记录活动热力图，近四个月             记录活动热力图，近四个月
能力数值（完整宽度）                 能力数值 60% | 雷达 40%
体能  段位          50/100          13 维可查   | 实际值标签
进度条+可展开说明                    单维度趋势（全宽）
……全部未隐藏维度                   紧凑按钮选择，不强制等宽
[展开能力雷达图 v]
成长趋势

移动能力卡整行全宽，不用两张 flex 卡片并排。每个属性的名称/段位/数值尽量同一行，窄宽度允许元信息换行，数值不拆成 `51.7 /` 与下一行 `100`。所有未隐藏维度默认可见；hidden 不显示、disabled 保留且明确标「已关闭判定」，不再给整行文字设置 0.55 opacity 而降低可读性。默认不改变任一维度的可见性设置。

共同的游戏分数说明集中在能力数值标题下，避免每条重复同一段说明占屏。每项真实 `description` 仍可通过该项「说明」的原生 details 查看，不删除后端内容。子维度保留在所属主维度内，不合并到主维度分数、不加入雷达。

手机雷达图用原生 details 默认收起；桌面默认展开。图表容器至少 320px 高，展开后 `nextTick` 再 init/resize；容器宽度变化用 ResizeObserver 或已有 resize 配合明确的折叠事件处理，销毁时清理 observer、事件及图实例。保留动态轴上界和轴名真实值；增加可见说明「轴上界随当前数值缩放，不能跨截图只比较面积」。图形不承担唯一数值表达，前面的完整数值列表就是替代信息。

### 3.4 详情与待处理：阅读和行动分层

详情手机/桌面顺序相同，桌面阅读列最大 820px：返回手账→发生时间/保存时间→完整标题和原文→编辑动作→独立分析区→撤销区域。长标题按 24px/1.45 显示完整，不使用预览 clamp。长正文保持换行，2 万字仍能滚到分析与撤销动作。

分析区使用浅背景或一条边框，避免在主卡内反复套厚卡。主要动作按已有状态决定：没有建议时「现在分析」；建议就绪且现有条件允许时「确认入账」；needs_input 时「提交补充」承接原操作；处理中优先显示状态，取消为次级。复核、再次分析与查看依据保留，但放在辅助动作组；不得删掉解释、置信度限制或现有禁用条件。UI 选择主动作只改模板层级与样式，不改后端状态机或为实现层级新建动作身份。

不分析的记录仍显示所选意图；若当前产品允许用户之后主动分析，保留显式入口和费用提示，不因文案重排新增禁用规则。已确认记录的冻结、挑战记录的跳转处理、置信度低于 0.8 的禁用规则全部保留。撤销仍单独位于末尾，确认文案继续说明原文/审计保留、属性按真实流水回滚、已发金币保留；不以轻微 toast 替代确认。

待处理手机/桌面均为：返回今天→页标题→说明→待补充/待确认/稍后分析三个实际分组→预览列表。状态标签在元信息行，不占正文左列；标题两行摘要三行，与手账复用基础视觉。分组只来自现有 `state`，轮询仍为 5 秒且卸载清理，不给每次轮询加加载遮罩或自动抢焦点。初次加载、错误与空态区分，读取失败不展示「暂时没有待处理」作为确定结论。点击仍进入原记录详情，不在列表内快捷自动确认。

### 3.5 睡前回顾：一个日常主动作，冲突保持明确

### 3.6 我的与设置：常用入口优先

我的手机/桌面采用同一三组顺序，桌面不为四个链接做四张巨大等高卡：

1. **账号与数据**：账号名/时区，数据导出链接到 `/settings#data` 所表达的设置锚点；云模式退出登录。
2. **AI 配置**：模型与密钥链接到设置的模型区；旁边可见「使用自己的凭据与额度」说明。
3. **个人与游戏设置**：角色档案、规则锚点、挑战与奖励，保留原路由。

不要新建 hash 二级路由来实现节内跳转：项目使用 createWebHashHistory，使用 Vue Router 的 route hash 与正确 scrollBehavior，或采用已有 `/settings` 加 query 定位并在 mounted 后滚动。若不实现定位，链接仅去设置页并在顶部提供可见区块目录，不能生成会被路由误解析的链接。

未建档时基线面板仍在个人设置上方，内容与确认原样保留：「13 维各 50、80 启动币、未评估游戏起点、选择后不能用问卷覆盖」。美化不能自动建档或把基线当真实能力测量。账号隐私提示保留一段可见摘要，详细解释可折叠；运营方可接触服务器数据与 AI 分数局限不能全部隐藏。

### 6.2 全局布局与状态验收

需覆盖空数据、短记录、长标题、2 万字、无空格英文/URL、同日多条、模型未配、排队、运行、待补充、待确认、失败、取消、已确认、冻结、保存结果不明、回顾版本冲突、未建档。所有输入为虚构，不在截图里出现密钥或真实恢复码。

- 所测宽度页面 `scrollWidth` 不超过可视宽度，允许热力图自身滚动；记录最后一项能滚到固定底栏上方，避免误用全站隐藏溢出。
- 200% 文字下允许首屏目标失效，但内容、按钮与标签不得被裁掉；横向/纵向布局变化不清空已输入内容。
- 键盘 Tab 顺序与视觉顺序一致，焦点可见；隐藏选项不留下可聚焦控件；错误有文字且能关联字段。减少动画设置生效。
- 初始加载不与「空数据」混淆；失败不清空已有记录；保存成功与模型失败分开，业务错误说明和重试入口持续可见。
- 图表 resize/dispose 无重复实例与监听泄漏，折叠展开、方向切换、桌面/手机跨断点后仍可读；原有数值/日期口径不变。
- 至少一台用户常用手机检查键盘开合、浏览器时间选择、底部安全区、返回/刷新与退出重登。若只有模拟浏览器，交付中明确「真机未验」，不得写全部通过。

### 6.3 业务保护回归

| 场景 | 必须保持的结果 |
|---|---|
| 录入草稿、切页、刷新、账号切换 | 按既有账号隔离/清理策略恢复或清理，不串稿；时间与意图包含在原草稿内 |
| 保存双击、响应丢失、查询回执重试 | 一次操作同一 UUID 和 payload；结果不明仍保护输入；不因为折叠或重新渲染生成新身份 |
| now/later/never、未配模型、分析失败 | 先存原文；仅显式分析调用模型；模型失败不能宣称原文丢失；later 默认不变 |
| 详情编辑/冻结/挑战/低置信/撤销 | 原限制、版本与确认步骤保留；属性回滚按真实流水，已发金币保留 |
| 回顾多版本/历史时区/草稿 | 旧输入保留且可比较，预期版本不跳过；只引用事件，不重复发奖 |
| 模型设置/换供应商/测试/清除 | 主辅独立、云端允许供应商约束和 Key 绑定保持；测试显式且提示可能计费；不回显 Key |
| 基线、购买、豁免、挑战、目标 | 不改变结算、押金、余额、冻结、回执与操作 composable；美化不自动执行原主动动作 |
| 导出、备份、报告 | 现有范围与模式区分保留；展开不备份/生成；历史来源冻结含义不变 |
